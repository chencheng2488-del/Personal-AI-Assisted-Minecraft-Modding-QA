# 这是什么？

这是我在用 AI 辅助完成了我的第一个在 MCMOD 以及 CurseForge 上过审的 Minecraft Mod：

**Infinity What / 什么无限？**

之后，看着 Mod 的代码只能读懂最基本的类定义，但它们到底是干嘛的却毫无头绪，故而找 AI 边问边记载得到的 Markdown 文档。

> 本文档本质是**私人学习笔记**，写给我自己看的，说白了，我是把Github当一个免费且格式最丰富、最好用的线上Markdown文档编辑器以及查看器和托管处，反正Github又不是不允许。选择公开，只是希望万一能帮到和我处境相同的人——AI 帮你写完了 Mod，而你想真正看懂它。能力有限，难免有幼稚或不准确之处，**不喜勿喷**；觉得有用点个 Star 就很开心了。

## 为什么会有这个仓库

Mod 做完、过审、发布，和**真正看懂自己 Mod 的代码**，完全是两回事。

AI 能一口气吐出能编译、能运行、能过审的工程，但作为作者，我打开源码后的真实状态是：

- 每个单词都认识，但不知道这个类为什么必须存在；
- 教程说"先注册"，却没人解释不注册会怎样、注册到底是登记给谁看；
- Gradle 一跑就是几分钟，红屏报错也不知道是代码问题还是网络问题；
- 想自己改点东西，不知道该动哪个文件，更不敢动。

于是我决定不追求"系统学完 Forge 再动手"，而是**以这个已经能跑的 Mod 为案例，看不懂什么问什么，一问一答记下来**。这个仓库就是问答记录的原件，按时间顺序排列，没有为了"看起来系统"而事后重写。

## 文档里有什么

问答以我这个零基础视角推进，大致路线是：

1. 项目整体结构与功能拆解；
2. `src/generated` 能不能删；
3. 代码里有哪些"AI 生成"的痕迹（顺带做了一次包名重构 `cn.autoforged.xxx` → `com.bandybus.infwhat`）；
4. **注册是什么** —— 为什么每个 Mod 都逃不掉 DeferredRegister；
5. 注册类能不能直接复制粘贴 —— 哪些是骨架、哪些空必须自己填；
6. 整个项目的文件结构为什么这么安排，哪些必须、哪些可删；
7. Gradle 是什么、和 Maven 的关系、国内网络怎么办；
8. `extends` 与"方块注册"的区别；
9. 开发时到底要不要抱着 API 手册，以及去哪里查资料。

越靠后的问题越接近"如何独立开发"，而不是"这段代码什么意思"。

## 运行环境

| 项 | 版本 |
|---|---|
| Minecraft | 1.20.1 |
| Forge | 47.4.10 |
| Java | 17（工具链），本机 JDK 21 |
| 构建 | Gradle + ModDevGradle (legacyforge) |
| Mod ID | `infwhat` |

注意：问答中的结论**只保证对以上版本成立**。Minecraft Mod 开发的 API 每个大版本都可能变动，换版本（尤其 1.21 / NeoForge / Fabric）时请勿直接照搬。

## 适合谁看

- 和我一样，AI 帮你生成了 Mod，但你想搞懂它写了什么；
- 看过几期 Forge 教程，仍卡在"注册""BlockEntity""Capability"这些黑话上；
- 不想先啃厚教程，希望从一个真实的小工程（两个方块、两千行内）入门。

不适合找"从零教你写 Mod"的系统课程——这份文档是问题驱动的，结构上并不完整。

## 怎么用

- 按顺序读，能看到一个真实新手的困惑是怎么一层层展开的；
- 也可以直接挑你也想问的问题看，每问独立成篇；
- 文档里的文件路径、行号基于当时的源码快照（2026.9.29,v1.0.0b,若要参考,请以此版本为参考），可能与 Mod 仓库后续提交有出入。
